# Интерфейс панели: визуальная система и поведение элементов

Панель оформлена по гайдбуку Aéza 2026. Токены лежат в [web/src/styles/tokens.css](../web/src/styles/tokens.css), компоненты — в [web/src/components/controls.tsx](../web/src/components/controls.tsx), макеты и компоненты с состояниями — в Figma (см. раздел «Figma»).

## Кнопки

| Вариант | Когда | Вид |
|---|---|---|
| `primary` | одно главное действие в блоке: «Сохранить и пересчитать», «Отправить в поток», «Войти» | голубая заливка, чёрный текст |
| `secondary` | равноправные действия: «Предпросмотр», «Включить правила», «Заменить модель» | белая, чёрная обводка 1.5 px |
| `dark` | акцент на тёмном фоне | чёрная заливка, белый текст |
| `ghost` | отмена и сброс: «Отменить изменения», «Очистить» | без фона |
| `danger` | необратимые действия только после подтверждения: «Пересоздать snapshot системы» | красная заливка |

Размеры: `md` 40 px (по умолчанию), `sm` 32 px. Радиус 10 px, шрифт Exo 2 700.

Состояния:

- **hover** — заливка темнее на ступень (`primary` `#2CB4E3`, `secondary`/`ghost` фон `#F4F4F4`);
- **pressed** — ещё темнее и сдвиг на 1 px вниз;
- **focus-visible** — двойное кольцо белое 2 px + чёрное 2 px (видно на любом фоне, в том числе на голубой кнопке);
- **disabled** — серая заливка `#EBEBEB`, текст `#9A9A9A`, курсор `not-allowed`; кнопка не в порядке Tab;
- **loading** — `aria-busy="true"`, подпись прозрачная (ширина не прыгает, диктор читает название), по центру спиннер; повторный клик игнорируется, кнопка остаётся в фокусе.

Кнопка становится доступной, только когда действие имеет смысл: «Сохранить» — при изменённом черновике, «Отправить в поток» — когда выбраны тип, клиент и (для событий услуги) услуга.

## Выпадающий список (Select)

Паттерн WAI-ARIA «combobox только для выбора»: триггер `role="combobox"` с `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`; список `role="listbox"`, варианты `role="option"` с `aria-selected`. Фокус всё время остаётся на триггере.

| Действие | Закрытый список | Открытый список |
|---|---|---|
| Клик по триггеру | открыть, подсветить выбранный вариант | закрыть |
| ↓ / ↑ / Enter / Space | открыть | ↓/↑ — следующий/предыдущий доступный вариант |
| Home / End | открыть на первом/последнем доступном | первый/последний доступный |
| PageDown / PageUp | — | через 10 вариантов |
| Буква | открыть на первом варианте с этой буквы | поиск по началу подписи; повтор одной буквы — по кругу между вариантами на неё; пауза 600 мс сбрасывает поиск |
| Enter / Space / клик по варианту | — | выбрать, закрыть, вернуть фокус на триггер |
| Alt + ↑ | — | выбрать подсвеченный и закрыть |
| Esc | — | закрыть без изменений, фокус на триггере |
| Tab | переход дальше | закрыть без изменений и перейти дальше |
| Клик вне списка | — | закрыть без изменений |

Подробности:

- недоступные варианты (`aria-disabled`, серые) пропускаются стрелками и не выбираются кликом — например, удалённая услуга в конструкторе событий;
- выбранный вариант отмечен галочкой и полужирным шрифтом; вариант может иметь вторую строку-описание;
- список открывается вниз, а если снизу меньше 300 px и сверху больше места — вверх; высота до 288 px с прокруткой, подсвеченный вариант прокручивается в видимую область;
- состояния триггера: обычное (обводка `#C7C7C7`), hover (`#6E6E6E`), открыт/фокус (чёрная обводка и голубое кольцо 3 px), ошибка (красная обводка, текст ошибки под полем), недоступен (фон `#F4F4F4`, серый текст);
- пустой список показывает «Нет вариантов»; плейсхолдер описывает следующий шаг («Сначала клиент», «Загрузка…»).

Используется: фильтр состояния оценки и мобильная сортировка в «Клиентах», тип записи в журнале, тип события, клиент, услуга и варианты полей в конструкторе.

## Галочка (Checkbox)

Нативный `input type="checkbox"` лежит прозрачным прямо над фирменным квадратом 20 × 20 (радиус 6): клавиатура, формы и диктор работают как у обычной галочки.

- **unchecked** — белый квадрат, обводка `#9A9A9A`; hover — чёрная обводка;
- **checked** — голубая заливка `#4CC6F1`, чёрная галочка;
- **indeterminate** — голубая заливка, чёрная черта, `aria-checked="mixed"`; клик выбирает всё;
- **focus-visible** — двойное кольцо как у кнопок;
- **disabled** — серая заливка, подпись серая; отмеченная — серая заливка с галочкой;
- **error** — красная обводка и текст ошибки под полем.

Space переключает, клик по подписи — тоже. Подпись может иметь описание (`aria-describedby`). Галочка меняет черновик формы; действие применяется по кнопке «Сохранить». Для мгновенных действий без сохранения предназначен переключатель `Switch` (`role="switch"`).

## Выбор режима (ChoiceCards) и сегменты

Крупные карточки-радиокнопки для решения, которое меняет поведение всей системы: «Чем считается основной балл», «Источник snapshot системы». Стрелки только переводят фокус между карточками, выбор — кликом, Enter или Space. Если выбор применяется на сервере (режим балла), вызывающая страница сначала показывает диалог подтверждения с последствиями. Выбранная карточка — чёрная рамка 2 px и голубая точка.

Сегменты (`Segmented`) — для коротких локальных переключений внутри карточки; стрелки сразу выбирают соседний вариант.

## Страница «Модель риска»

1. **Чем считается основной балл** — две карточки: «ML-модель» (по умолчанию) и «Правила». Смена режима — через диалог с последствиями; аналитик видит карточки недоступными. Если выбран ML, а модель не загружена или не выполнилась, под карточками предупреждение: расчёт идёт правилами.
2. **Правила выключены** (режим ML) — пунктирная плашка с кнопкой «Включить правила». Веса, окно срочности и предпросмотр в этом режиме скрыты: на балл они не влияют, а сохранённые значения не теряются.
3. **Правила: признаки и веса** (режим правил) — ползунок и числовое поле для каждого признака, разница с сохранённой ревизией, окно срочности; кнопка «Предпросмотр» показывает, сколько клиентов сменит уровень и как изменятся деньги, до сохранения.
4. **Уровни, деньги и время оценки** и **Определения оттока** — доступны в обоих режимах: пороги уровней, горизонт денег, режим часов и шаг пересчёта по времени, окна оттока.
5. «Сохранить и пересчитать» создаёт новую ревизию настроек: изменения переживают перезапуск, баллы, рейтинг и деньги обновляются без перезагрузки страницы; при одновременной правке — диалог конфликта ревизий.
6. Карточка ML-модели: пакет, проверка на отложенном периоде против правил, текущий расчёт и исходы, загрузка/замена/отключение пакета.

## Страница «Симуляция»

Симуляция работает постоянно: паузы нет, после перерыва симулятор догоняет время.

**Собрать событие**: тип → клиент (поиск по ID или email, сначала самые рискованные) → услуга (для событий услуги; удалённые недоступны) → поля события (сумма в евро, оценка, направление, категория, галочка автопродления). Блок «Что уйдёт в поток» показывает итоговый JSON. «Отправить в поток» ставит событие в очередь симулятора; он применяет событие к snapshot системы так же, как действие самого клиента, и отправляет его в общий поток со следующим номером события аккаунта. В списке «Последние собранные события» статус меняется сам: «в очереди симулятора» → «в потоке» (с eventId) или «не применено» с причиной (например, «Клиент уже ушёл»). При пересоздании snapshot системы ожидающие события отклоняются.
